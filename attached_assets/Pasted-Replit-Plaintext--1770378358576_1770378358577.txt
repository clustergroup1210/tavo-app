Replit用プロンプト（横スクロール前提・評価マトリクス表の実装）
Plaintext
あなたは複雑なデータ表示を得意とするフロントエンドエンジニアです。
現在開発中の「チームダッシュボード」にあるリスト表示を廃止し、**「選手別・時系列評価マトリクス表（ヒートマップ）」**へ刷新してください。

## 1. UI/UX方針
- **全デバイス共通レイアウト:** PC・タブレット・スマホ問わず、**「横スクロール」**を前提としたテーブルレイアウトとします。無理なレスポンシブ崩し（カード化など）は不要です。
- **固定表示 (Sticky):** 横スクロールした際に「誰のデータか」がわからなくならないよう、左側の列（背番号・名前・項目）を常に画面左端に固定表示してください。

## 2. 実装詳細

### A. テーブル構造
以下のカラム構成でHTML `<table>` を構築してください。

| 固定エリア (Sticky Left) | スクロールエリア (Overflow-x) |
| :--- | :--- |
| **背番号** | **氏名** | **項目 (Element)** | **2024/04** | **2024/05** | **...** |

- **行の構成:** 1人の選手につき、評価カテゴリ（心・技・体・戦術など）の数だけ行を作ります（Rowspanで背番号と氏名を結合すると見やすくなります）。
- **ソート:** デフォルトは「背番号（昇順）」です。

### B. スタイル要件 (Tailwind CSS)
- **コンテナ:** `w-full overflow-x-auto` で横スクロール領域を作成。
- **セル:** `whitespace-nowrap` を指定し、日付や名前による改行を防ぐ。
- **固定列 (Sticky):**
  - 背番号・氏名・項目の `th`/`td` には `sticky left-0` (2列目以降は `left-[px]`計算が必要、または `position: sticky` の重ね合わせ) を適用し、背景色(`bg-white`等)を必ず指定して透けないようにする。
  - **Z-index制御:** 固定列がスクロール列の上に重なるよう `z-10` 等を適切に設定する。
- **ヒートマップ色:**
  - 各月のセルは、達成率やスコアに応じて背景色を変える。
  - 例: `bg-red-500` (低), `bg-yellow-400` (中), `bg-blue-100` (高)。

## 3. 依頼内容

### Step 1: データ取得と整形 (Server Action)
`getEvaluationMatrix(teamId)` を作成してください。
- チーム所属選手の全評価履歴を取得。
- フロントエンドで描画しやすいよう、以下の形式に変換して返却する。
  ```typescript
  // 返却データイメージ
  {
    months: ["2024/04", "2024/05", ...], // ヘッダー用日付リスト
    players: [
      {
        id: "...",
        number: 1,
        name: "選手名",
        rows: [
          { category: "技術", scores: [10, 12, 15, ...] }, // monthsに対応するスコア配列
          { category: "戦術", scores: [5, 6, 8, ...] }
        ]
      },
      // ...
    ]
  }
Step 2: コンポーネント実装 (EvaluationMatrixTable)
上記データを受け取り、テーブルを描画するコンポーネントを作成してください。

左3列（背番号・名前・項目）の固定表示実装は、CSSの position: sticky を正確に使用し、スクロール時の違和感がないようにしてください。

### 💡 Replitへの補足アドバイス

もしReplitが書いたコードで「スクロールすると名前が透けて、後ろの数字と重なって見にくい」という現象が起きたら、それは**「Sticky要素に背景色が指定されていない」**ことが原因です。

その場合は、以下の追加指示を出してください。
> 「左側の固定列（Sticky列）に `bg-white` (またはダークモードなら `bg-gray-900`) を明示的に指定して、スクロールしたデータが透けて見えないように修正してください」
