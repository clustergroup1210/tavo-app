画像の「選手データ管理」および「選手移籍時のデータ可視範囲」は、**「いつ、どのチームにいたか」によって、データの見える・見えないを厳密に制御する**という、非常に高度なロジックが求められる部分です。

特に**「新チームは、過去（旧チーム時代）のデータを見れない」「旧チームは、移籍後のデータを見れない」**という**双方向の遮断（時系列フィルタリング）**を実装する必要があります。

これをReplitに正確に実装させるためのプロンプトを作成しました。

### Replit用プロンプト（選手移籍とデータ閲覧スコープの制御）

```text
あなたはデータプライバシーとマルチテナント設計に強いバックエンドエンジニアです。
現在開発中のシステムに、添付画像の要件に基づく「選手移籍機能」および「厳格なデータ閲覧スコープ制御」を実装してください。

## 1. 要件定義 (画像に基づく詳細仕様)
選手がチームを移動（移籍）した際、データの所有権は選手本人に属しますが、**「どのチームがどのデータを見れるか」**は時系列によって厳密に制限されます。

### A. データ管理の原則
- すべてのデータ（評価、動画、目標等）は `TeamID` ではなく `PlayerID` (User) に紐づく。
- 物理削除は行わず、全ての履歴をDBに残す。

### B. 閲覧スコープ (Access Control Logic) **最重要**
データを取得する際、閲覧者によって以下のフィルタリングを強制してください。
1. **選手本人:** 過去から現在までの**全データ**を閲覧可能。
2. **旧チーム (過去の所属):**
   - **閲覧可能:** 自チームに在籍していた期間(`joinedAt` 〜 `leftAt`) のデータのみ。
   - **閲覧不可:** 移籍後の新しいデータ、および移籍時点の「マイページスナップショット」も通常画面では閲覧不可。
3. **新チーム (現在の所属):**
   - **閲覧可能:** 自チームに移籍して以降(`joinedAt` 〜 `now`) に蓄積されたデータのみ。
   - **閲覧不可:** **以前のチーム在籍時のデータ（過去データ）は見せない**（真っ白な状態でスタート）。

## 2. 依頼内容

### Step 1: schema.prisma の拡張
移籍履歴を管理する `TransferHistory` モデルを作成してください。

```prisma
model TransferHistory {
  id          String   @id @default(cuid())
  playerId    String
  fromTeamId  String?
  toTeamId    String
  transferredAt DateTime @default(now())
  
  // 移籍時点のマイページ状態（スナップショット）
  snapshotData Json?    // 達成率、評価スコア等をJSONで固定保存

  player      User     @relation(fields: [playerId], references: [id])
  // 必要に応じてTeamへのリレーションも追加
}

```

### Step 2: 移籍処理の実装 (Server Action)

`transferPlayer(playerId, newTeamId)` アクションを作成してください。
以下の処理をTransaction内で実行すること。

1. 現在の `TeamID` を取得。
2. `TransferHistory` レコードを作成（`fromTeamId` = 現在, `toTeamId` = 新, `snapshotData` = 現在のステータス）。
3. `User` テーブルの `currentTeamId` を更新。

### Step 3: データ取得時のフィルタリング関数 (Data Access Layer)

評価や動画などのリストを取得する際、閲覧者の立場に応じてクエリ条件（Where句）を動的に生成するユーティリティ関数 `getVisibleDateRange(viewer, targetPlayer)` を実装してください。

**ロジックイメージ:**

* Viewerが「現在のチーム」の場合:
* `TransferHistory` から「最新の加入日(latestJoinDate)」を取得。
* `WHERE createdAt >= latestJoinDate` を適用。


* Viewerが「過去のチーム」の場合:
* `TransferHistory` から「在籍開始日」と「移籍日」を取得。
* `WHERE createdAt >= startDate AND createdAt <= endDate` を適用。

### 💡 実装のポイント
