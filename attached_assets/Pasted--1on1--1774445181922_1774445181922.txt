### Replit用プロンプト（メンタリング記録機能の実装）

```text
あなたはUI/UXとデータベース設計に強いフルスタックエンジニアです。
現在開発中のシステムに、添付画像（メンタリング記録の表）に基づく「月次メンタリング記録機能」を実装してください。

## 1. 要件定義

### A. 目的と配置
- 選手と指導者が毎月の目標とフィードバックを共有するための機能です。
- 選手の「マイページ（または選手詳細画面）」に、新しく『メンタリング』というタブを追加し、そこにこの表を表示してください。

### B. データ構造と表示項目
月（例：2024/4、2024/5...）ごとに以下のデータを管理・表示します。
1. **目標 (Goal):** その月のテーマや目標（テキスト）。主に選手が入力。
2. **スタッフコメント (Staff Comment):** 指導者からのフィードバック（テキスト）。指導者が入力。
3. **評価点 (Score):** その月の達成度などのスコア（1〜5の数値など）。指導者が入力。
- **ヘッダー機能:** 表の一番上には、これまで入力された「評価点」の**平均値**を計算して表示してください（画像右上の「2.74」のようなイメージ）。

### C. 権限とアクセス制御
- **選手:** 自分の「目標」を入力・編集できる。「スタッフコメント」「評価点」は閲覧のみ。
- **指導者（担当コーチ・監督）:** 選手の「目標」を閲覧でき、「スタッフコメント」「評価点」を入力・編集できる。

## 2. 依頼内容

### Step 1: schema.prisma の拡張
月次の記録を保存する `MentoringRecord` モデルを作成してください。

```prisma
model MentoringRecord {
  id           String   @id @default(cuid())
  playerId     String
  targetMonth  String   // 例: "2024-04"
  goal         String?  @db.Text
  staffComment String?  @db.Text
  score        Int?     // 例: 1〜5の段階評価

  player       User     @relation(fields: [playerId], references: [id])

  @@unique([playerId, targetMonth]) // 1人の選手につき各月1レコードのみ
}
```
※作成後、Prismaクライアントの再生成（`npx prisma db push`等）が必要な旨を私に伝えてください。

### Step 2: データ操作ロジック (Server Actions)
- `getMentoringRecords(playerId)`: 対象選手の全記録を取得する処理。
- `upsertMentoringRecord(playerId, targetMonth, data)`: 記録を保存・更新する処理。権限に応じて更新できるフィールド（goalのみか、comment/scoreもか）を制御してください。

### Step 3: UIコンポーネントの実装 (`MentoringTable`)
- 画像のようなスプレッドシート風のテーブルUIを作成してください。
- **行の自動生成:** 選手の「入団年月」から「現在（または指定の未来月）」までの行を自動で生成し、DBにデータがない月でも入力フォーム（空欄）として表示されるようにしてください。
- 各セルは、権限に応じて「テキストテキストエリア」または「表示のみ」に切り替わるようにしてください。評価点はプルダウン（Select）が望ましいです。

## 技術スタック
- Next.js (App Router), Prisma, Tailwind CSS
```
