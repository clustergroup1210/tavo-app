```text
あなたはアーキテクチャ設計に強いバックエンドエンジニアです。
現在開発中のシステムにおいて、添付画像の要件に基づく「基準クラブ（VEDIALO CF）アカウント」および「評価項目のテンプレート管理機能」を実装してください。

## 1. 要件定義 (画像に基づく詳細仕様)

### A. 基準クラブ「VEDIALO CF」の役割
- システム内に「VEDIALO CF」という基準となる特別なチーム（アカウント）を作成する。
- このアカウントには、あらかじめ標準的な「評価項目マスター」が初期設定としてすべて登録されている状態にする。

### B. 一般チームの初期状態とテンプレート適用
- 一般のチームが新規作成された時点では、評価項目は「空（または最小構成）」とする。
- 一般チームは、必要に応じて「VEDIALO CF」の評価項目セットを自チームに「コピー（適用）」することができる。

### C. カスタマイズ性
- テンプレートからコピーした評価項目は、各チームで自由に「追加」「編集」「非活性化（削除ではなく使わなくする）」ができるようにする。

## 2. 依頼内容

### Step 1: schema.prisma の拡張
評価項目が「システム全体」ではなく「各チーム」に紐づく設計にし、非活性化やテンプレート管理ができるようにしてください。

```prisma
model EvaluationItem {
  id              String   @id @default(cuid())
  teamId          String   // どのチームの評価項目か
  category        String   // 大項目 (例: 個人技術)
  name            String   // 小項目 (例: ボールコントロール)
  maxScore        Int      @default(4)
  isActive        Boolean  @default(true) // カスタマイズ用: 非活性化フラグ
  
  // テンプレートからコピーした際の追跡用（任意）
  originalItemId  String?  

  team            Team     @relation(fields: [teamId], references: [id])
  records         EvaluationRecord[]
}

```

### Step 2: シードデータ (Seed) の作成または更新

`prisma/seed.ts` 等に以下の処理を追加してください。

1. `name: "VEDIALO CF"` という基準チームを作成する。
2. そのチームに対して、標準的な評価項目（ダミーで構いませんので、心・技・体・戦術の数十項目）を一括登録する。

### Step 3: テンプレート適用ロジック (Server Actions)

一般チーム向けに、以下の関数を作成してください。

1. **`applyTemplateItems(targetTeamId)`**
* 「VEDIALO CF」チームの `EvaluationItem` を全件取得し、`targetTeamId` 用に複製（コピー）して保存する処理。


2. **`toggleEvaluationItemActivity(itemId, isActive)`**
* チーム管理者が不要な項目を「非活性化」するための処理（物理削除はしない）。



### Step 4: UIの実装案（チーム設定画面）

* チーム管理者の設定画面に「評価項目管理」タブを作成。
* 評価項目が0件の場合は、「基準テンプレート（VEDIALO CF）から項目をインポートする」というボタンを表示する。
* インポート後は、各項目のON/OFF（非活性化）を切り替えるスイッチと、独自項目を追加するボタンを配置する。

## 技術スタック

* Next.js (App Router), Prisma

### 💡 実装のポイント
この設計の肝は、**「最初から全チームに同じ評価項目を強制しない」**という点です。
あえて「VEDIALO CF」というテンプレート用のダミーチームを作ることで、将来的に「強豪校Aの評価セット」「育成クラブBの評価セット」のように、複数のテンプレートを選べるような拡張も簡単にできるようになります。

Replitがコードを生成した後は、必ず `npx prisma db seed` などのコマンドを実行して、VEDIALO CFの初期データがデータベースに入るようにしてください。
